# 5. Customer segmentation and buying process

**As-of:** 9 November 2025  
Ranges are **Working assumptions** until interviews.

## Ideal customer profile (ICP)

| Dimension | Range |
|-----------|-------|
| Business activity | CNC / fabrication / maintenance / marine services / small assemblies |
| Employees | 5–75 FTE |
| Turnover | £1m–£25m *(assumption)* |
| Incoming qualification packs | 6–30+ / year |
| Distinct customers with different templates | 3–15 |
| Current software | Microsoft 365 or Google Workspace; maybe ISO 9001-lite QMS |
| Admin resources | 0.5–1.5 FTE office/quality hybrid |
| Document sensitivity | Medium–high (insurance, financials, H&S) |
| Purchasing authority | MD can approve £99–£249/mo without board |

## Buying roles

| Role | Typical title | Job |
|------|---------------|-----|
| Economic buyer | MD / Ops Director | Approves spend; cares about risk and time |
| Daily user | Quality / admin coordinator | Runs packs |
| Approver | MD or designated competent person | Signs off statements |
| Gatekeeper | IT / sometimes customer procurement | MFA, DPA, “can we upload?” |
| Beneficiary | Estimators / engineers | Less document chase |

## Buying triggers

- New framework / OEM / operator customer  
- Insurance or certificate renewal wave  
- Failed or delayed submission  
- Audit finding on document control  
- Lost opportunity attributed to incomplete pack *(self-reported — treat carefully)*

## Budget source

Opex / admin / quality budget; compared mentally to consultant day rates (£400–£800) and Constructionline-like memberships. *(Reasoned inference.)*

## Purchase objections

| Objection | Response direction |
|-----------|-------------------|
| “We have Constructionline” | Different job — multi-customer packs vs one register |
| “SharePoint is enough” | Measure hours; pilot proves delta |
| “Confidential — can’t upload” | DPA, MFA, UK/EU hosting, deletion; optional concierge on-site |
| “Too few packs” | Anti-persona; do not sell |
| “AI will invent answers” | Evidence-only + human approve; abstain |

## Switching costs

Low from spreadsheets (data import labour is the cost). Medium if already paying tender AI and expecting it to cover private PQQs.

## Sales-cycle assumptions

| Stage | Duration |
|-------|----------|
| First reply → discovery call | 1–2 weeks |
| Discovery → pilot | 1–3 weeks |
| Pilot (4 weeks) → paid sub | Immediate to 2 weeks |
| Total founder-led | 6–10 weeks |

*(Working assumption.)*

## Anti-personas (do not target)

- Sole traders with &lt;2 questionnaires/year  
- Firms only bidding public sector with a working tender subscription and no private packs  
- Enterprises needing full procurement suite / SSO / custom SSO in week one  
- Buyers seeking a supplier directory or accreditation scheme  
- Holiday-let operators (rejected fallback)
